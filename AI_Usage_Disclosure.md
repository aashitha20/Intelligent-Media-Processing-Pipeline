# AI Usage Disclosure

This document discloses how AI assistance (Cursor Agent) was used while building and validating the **Intelligent Media Processing Pipeline** project.

---

## Scope of AI Assistance

AI was used as a coding agent to help implement, test, debug, and document the project described in `PROJECT.md`. A human developer directed the goals, reviewed outputs, and made deployment/configuration decisions (for example, Redis credentials and Vercel hosting).

---

## What AI Helped With

### 1. Project setup and architecture
- Reviewed `PROJECT.md` goals, deliverables, and the proposed tech stack
- Assessed tool fit (Express, Prisma, BullMQ, Sharp, Tesseract, etc.)
- Noted that native OpenCV Node bindings are fragile and implemented blur detection with Sharp Laplacian variance instead
- Scaffolded the Node.js + TypeScript project structure, Express API, Prisma schema, BullMQ worker, and modular analysis pipeline

### 2. Feature implementation
- Implemented API endpoints:
  - `POST /upload`
  - `GET /status/:id`
  - `GET /result/:id`
  - `GET /failure/:id`
- Implemented analysis modules:
  - blur, brightness, duplicate hash, OCR, Indian number-plate validation, dimensions, metadata
- Added Swagger docs, Pino logging, Zod validation, Vitest tests, and `docker-compose` for Postgres/Redis

### 3. Testing and validation
- Ran end-to-end tests on sample images `image_1`, `image_2`, and `image_3`
- Documented observed results in `TEST_RESULTS.md`
- Fixed upload MIME validation (WebP / `application/octet-stream` 400 errors)
- Tightened number-plate OCR fallback to reduce false positives from OCR noise

### 4. Deployment investigation
- Investigated Vercel `FUNCTION_INVOCATION_FAILED` / `500 INTERNAL_SERVER_ERROR`
- Identified serverless incompatibilities (Express `listen()`, BullMQ workers, local filesystem uploads)
- Added Vercel serverless adapter (`api/index.ts`, `vercel.json`), inline processing mode, and `/tmp` uploads
- Documented findings and limitations in `DEPLOYMENT_REPORT.md`

### 5. Documentation and operations support
- Wrote / updated README guidance for local runs without Docker
- Explained where Redis is configured (`REDIS_URL` in `.env`)
- Produced this AI usage disclosure based on the development chat

---

## What AI Did Not Do Alone

AI did **not** independently:
- Own the product requirements (those came from `PROJECT.md` and the user)
- Provide or invent production secrets as project policy; the user supplied Redis connection details when requested
- Fully verify the live Vercel deployment from the agent environment when Deployment Protection / SSO blocked public access
- Replace human judgment for academic integrity, grading, or final submission decisions

---

## Human Oversight

The human developer:
- Defined the MVP goals and asked for implementation, testing, and deployment fixes
- Ran / requested local commands (for example, `docker compose`, uploads, status/result checks)
- Provided production Redis URL values when configuring the environment
- Remains responsible for reviewing code, validating deployment, and submitting the assignment

---

## Tools and Models

- **Environment:** Cursor Cloud / Cursor Agent coding assistant
- **Repository work:** feature branch development, commits, pull requests, tests, and markdown reports
- **Runtime used during development:** local Node.js API + worker, PostgreSQL, Redis (and later Railway Redis URL supplied by the user)

## Accuracy and Limitations

- Image analysis quality (especially OCR / number-plate extraction) is MVP-level and can produce noisy or incomplete text.
- On Vercel, background BullMQ workers are not supported; processing uses inline mode with documented limitations.
- AI-generated code should be reviewed before production use beyond the assignment scope.

---

## Statement

AI assistance was used openly to accelerate implementation, debugging, testing, and documentation of this project. The work product should be understood as **human-directed, AI-assisted engineering**, not fully autonomous authorship without oversight.
